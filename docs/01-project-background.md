# Project Background

## Why I Started This Project

I began developing the UAS Program Management System (UAS PMS) to improve how information associated with an Unmanned Aircraft System (UAS) program is organized, maintained, and used.

Managing a UAS program involves many different types of information. Aircraft, batteries, equipment, pilot qualifications, training, flight activity, aircraft checkouts, maintenance records, and reporting requirements all have to be tracked. When information is maintained across separate files, spreadsheets, forms, and other sources, routine administrative tasks can become time-consuming and information can be difficult to connect.

I saw an opportunity to use Microsoft 365 tools to create a more structured approach.

## My Approach

Rather than treating each spreadsheet or form as an independent solution, I began designing the project as a connected information management system.

Microsoft Lists became the foundation of the system. I created separate lists for different categories of information and defined the fields needed within those lists. Where appropriate, I began using lookup fields and relationships so information could be connected instead of repeatedly entered in multiple locations.

Microsoft Forms provides a simpler method for entering certain types of information. Data submitted through Forms can be captured in Microsoft Lists and then used by other components of the system.

I have also connected portions of the Microsoft Lists environment to Microsoft Excel. Using Power Query, information stored in Lists can be brought into Excel and refreshed rather than manually recreating the same information for analysis and reporting.

## What I Have Built So Far

The project is still under active development, but several foundational components have already been built and tested.

Work completed or underway includes:

- Designing the overall UAS PMS structure.
- Creating multiple Microsoft Lists and defining their fields.
- Building lookup relationships between related information.
- Implementing Microsoft Forms for selected data-entry workflows.
- Connecting Microsoft Lists data to Excel.
- Using Power Query to retrieve and refresh List data in Excel.
- Testing portions of the Forms-to-Lists-to-Excel workflow.
- Planning the reporting structure that will use the collected information.

Additional data structures, reporting capabilities, legacy-data migration, and workflow automation are still being developed.

## Design Philosophy

My goal is not simply to replace existing spreadsheets with newer spreadsheets.

I am working toward a system where information can be entered once, stored in a structured location, connected to related information, and reused for different operational and reporting needs.

The project is also an opportunity for me to apply and expand my knowledge of Microsoft 365, data relationships, workflow design, Power Query, reporting, and automation while solving a practical information-management problem.
